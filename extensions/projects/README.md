A project hub at the window's left edge: every project Ultimate has opened on this machine, running or stopped, one click away, and a way to add another. Each project stays its own Ultimate (its own process, state, trust decision and @ultimate); the hub only finds, starts and switches between them.

## How it works

- **Rail** (`shell.rail`, on desktop and tablet; the phone gets the project menu below): one row per project, in project order. It shows while at least two projects are known, running or not.
  - A stopped project (no live supervisor holds its lock) shows faded, `stopped` under its name. A click starts it (`open`), says "starting…" and goes there once it listens; a failure becomes a notice. **Add project…** at the end of the list, and ⌘K **Add project…**, open a dialog that takes a folder path (`~` allowed) and does the same for a new folder; a page opened over the tailnet cannot add one.
  - Collapsed, the rail is one quiet column of colour, a swatch per project and no letters (`ProjectSwatch` from the sidebar). Ultimate's own family (`ultimate`, `ultimate-eval`, a branch checkout of it) is the brand purple; every other project takes a muted, cool hue (sage, teal, blue; no warm hues, so nothing reads as amber or red, and no violet, which stays Ultimate's), derived from the folder name alone (`colourOf` in the sidebar's `tile.tsx`, small and exported for other overviews), so a project keeps its colour on every instance and in the sidebar's header. Projects sharing a name stem (`ultimate`, `ultimate-eval`, `ultimate-fleet`) take neighbouring shades of one hue, and their adjacent swatches join into one strip with a gap before the next family. Other projects' swatches are slightly faded until hovered; the one this page shows is wider and full colour, ringed, with a brand bar on the edge. The swatch, its amber count and its working dot share the column's vertical axis.
  - Hovering opens it over the app (272 px); the pin button keeps it open beside the app. Each row then shows the display name (`prettyName`), and under it the GitHub `owner/repo` with a lock when private, and the port. The pin is one value for every instance on this machine (`~/.ultimate/projects-rail.json`), so jumping keeps the rail as it was.
  - On a page opened over the tailnet a row goes to the host the page came from, on that project's Tailscale port (`tailnetPort`, from the registry `~/.ultimate/tailscale.json`), since a loopback address means nothing there. A project not published on the tailnet shows dimmed, with no link. `links.ts` decides both from the page's host.
  - A row is a plain link to the instance's `/`, which opens its @ultimate: a click goes there in this tab, mod-click or middle-click opens a new tab, Back returns. The old page stays until the new one paints (seconds while the target builds its web bundle), so a click pulses its swatch, says "opening…" and runs a thin brand bar along the window's top; a page restored by Back clears it.
  - Live state, polled every 4 s while the tab is visible: an amber count of questions waiting for the user, else a pulsing brand dot while an agent works (questions outrank working; the two never show together). Folded, they sit on the swatch: amber is the only warm colour in the column, so a project waiting on you stands out. The footer sums it up (`1 for you · 2 working`).
- **Phone:** the title bar's project chip (`titlebar.project`) becomes a menu of the same projects, asked again each time it opens: each goes there as a rail row does, a stopped one starting first, with its questions or working dot, then **Add project…**.
- **Another rail wins:** when any other enabled extension fills `shell.rail` (a fleet switcher of your own, say), this one renders nothing and stops polling, so the window never shows two rails; the phone chip stays plain.

## Files

- `server.ts`
  - `list`, `{}` → `Project[]` (`refs.ts`): every project home `host.projects()` finds whose folder still exists, each with its `root`, and its loopback `url` while it runs (its supervisor lock is held by a live process); a branch checkout's name is `<project> #<id>`, so it shows and colours with its project. Each carries its `origin`'s GitHub `repo` (`{name, url, visibility?}`) once known: read in the background on first sight (`git`, then one `gh repo view`) and kept for the process, so a poll never waits on it. This instance's `busy` and `questions` come from its own conversations and open questions; every other instance's from its `status` action over loopback, waiting at most 1.5 s. One that does not answer in time is listed without them.
  - `open`, `{ root }` → `{ url }` (user-only): the folder's Ultimate, started unless its lock names a live listener, the way `ultimate <root> --no-open` would from a terminal: detached in its own process group, without this server's `ULTIMATE_*` variables (but `ULTIMATE_USER_HOME`), on a free port. It answers once the new lock names a port, within 30 s; what the process printed before that goes to `<home>/start.log`, which a failure quotes. Agents cannot call it: they reach other projects with `ultimate.tell`, and starting a process is the user's choice.
  - `pin`, `{ pinned? }` → `{ pinned }`: the shared pin, written first when `pinned` is given.
- `web.tsx`: the rail, the phone's project menu, the Add project dialog and the opening bar.
